# SABAK+ v0.5 — электронный дневник (команда NEXUS)

PWA на чистом HTML/CSS/JS (без сборки). Два режима:
- **Демо** — данные в браузере, переключатель ролей, кнопка «▶ Демо» (сценарий для жюри).
- **Живой** — реальная база Supabase: вход, регистрация, приглашения, фото, «дела», аналитика.

## Что нового в 0.3
- Реальный вход и регистрация (4 шага: код → ФИО/данные → почта/пароль → готово), восстановление пароля.
- Фото профиля ученика с автопроверкой в браузере (одно лицо, размер, по центру, наклон, свет, резкость, фон, тёмные очки). Не прошло — сохранение отклоняется и показывается, что исправить.
- Классный руководитель и администрация отправляют «предупреждение о фото» (колокольчик у родителя/ученика).
- Автоопределение сети (без кнопки ⏻): пропала связь — работа продолжается, вернулась — очередь уходит сама.
- Новая шапка, «Сохранено/Отменить» вынесены в заголовок страницы.
- **Цепочка доверия** для администрации: ключ школы (выдаёт оператор) → директор → одноразовые приглашения сверху вниз → подтверждение директором/завучем → журнал аудита.
- «Дело» ученика (характеристика, документы КР: свидетельство о рождении, форма 026/у, прививки, и т.д.). Чтение — администрация; правка — родители и классный руководитель; ученик — доступа нет.
- Иерархия: директор → завуч → учитель (классный руководитель) → родитель/ученик. Мониторинг педагогов, аналитика (успеваемость, качество знаний, СОУ, корреляция, тренд, выбросы, выводы словами), диаграммы, экспорт в Excel / Word / PDF.

## Новое в 0.5
- **Специальные возможности** (кнопка ♿ в шапке или Alt+A, работает и до входа): 4 темы контраста (стандарт, контрастная светлая, тёмная, жёлтое на чёрном), палитра для дальтоников, размер текста до 200 %, интервалы, шрифт для дислексии, **облегчённый вид**, крупные кнопки, подчёркивание ссылок, отключение анимаций, озвучка страницы. Профили «Слабое зрение», «Дислексия», «Спокойный режим».
- **Анимации**: появление карточек, рост полос, счётчики, тряска колокольчика, подсветка достижений, конфетти. Выключаются настройкой и системным «уменьшить движение».
- **Достижения работают сами**: 13 правил (`js/achv.js`; на сервере — `evaluate_achievements` в `schema_v3.sql`, запускается триггерами на оценки, посещаемость и ДЗ). Пример: 30 учебных дней подряд без «Н» → «30 дней без «Н»», уведомление ученику и родителям. В демо на странице достижений есть кнопка «Смоделировать 30 дней без «Н»».
- **Администрация → классный руководитель**: в «деле» ученика, где администратор не может ничего менять, есть кнопка «Написать классному руководителю» со списком недостающих документов.
- **Предметы школы**: добавляйте свои предметы, скрывайте лишние (вкладка «1. Предметы»).
- **Расписание**: директор создаёт/публикует; завуч создаёт, но оно действует только после одобрения директора (при отклонении завуч получает причину); учитель читает и пишет комментарии завучу; ученик и родитель видят «бумажный дневник». Конструктор: смены и звонки (генератор по длине урока/перемен), смена по дням для каждого класса, **перетаскивание** (drag & drop) и режим «выбрал предмет — нажимай на клетки» (для телефона), проверка пересечений учителей и кабинетов, копирование дня/класса, версии.

### Обновление базы до 0.5 (один раз)
Supabase → SQL Editor → вставить **весь** файл `supabase/schema_v3.sql` → Run. (Файл `schema_v2.sql` повторно запускать не нужно.) Без этого шага приложение работает, но достижения, предметы школы и расписание в живом режиме недоступны. SQL-сценарии проверок: `supabase/tests_v3.sql`.

## Новое в 0.4
- **Подтверждение почты кодом.** После регистрации на почту приходит 6-значный код; пока его не ввести, Supabase не выдаёт сессию — аккаунт не работает. Можно отправить код повторно (раз в 60 с). Если при входе почта не подтверждена — приложение само предложит ввести код.
- **Серверная проверка фото** (Edge Function `verify-photo`) и «строгий режим» школы: фото принимает только сервер.
- **Кыргызский интерфейс** переведён целиком (~500 фраз; черновик, нужна вычитка носителем).
- **Политика данных** (RU/KY) — ссылка на экране входа и в меню профиля.
- Исправлена гонка синхронизации (только что добавленный ученик мог исчезнуть).
- Папка `tests/` с автотестами.

## Подтверждение почты: включение (5 минут)
1. Supabase → **Authentication → Sign In / Providers → Email** → **включите** «Confirm email».
2. **Свой SMTP** (без него Supabase не даёт редактировать шаблон): Authentication → **Emails → SMTP Settings** (или Project Settings → Auth → SMTP) → включите «Enable custom SMTP». Для хакатона проще всего Brevo (300 писем/день бесплатно, достаточно подтвердить один адрес-отправитель) или Gmail (пароль приложения). Подробно — в сообщении ассистента / ниже.
3. **Authentication → Emails → Templates → Confirm signup**: тема «Код подтверждения SABAK+», тело — содержимое `supabase/email/confirm-signup.html`. То же для **Reset password**: тема «Новый пароль SABAK+», тело — `supabase/email/recovery.html`. В письме обязательно должна остаться переменная `{{ .Token }}` (для кода) и `{{ .ConfirmationURL }}` (для ссылки смены пароля).
4. Хотите без подтверждения (быстрее на хакатоне) — оставьте «Confirm email» выключенным: приложение работает и так.

## Серверная проверка фото: включение
1. Supabase → **Edge Functions → Deploy a new function** → имя `verify-photo` → вставьте `supabase/functions/verify-photo/index.ts` и файл `core.js` рядом (или через CLI: `supabase functions deploy verify-photo`).
2. Выключите у функции «Verify JWT with legacy secret», если Dashboard предлагает (функция сама проверяет пользователя).
3. В приложении: директор → «Доступ» → отметка **«Серверная проверка фото»**.
Что проверяет сервер: формат JPEG, размер, формат 3:4, освещение, контраст, резкость, наличие кожи в центре кадра, права пользователя. Распознавание лица нейросетью остаётся в браузере — полноценная серверная проверка лица требует отдельного сервиса.

## Запуск живого режима (один раз)
1. Supabase → **Authentication → Providers → Email**: «Confirm email» можно оставить включённым (см. раздел «Подтверждение почты») или выключить — приложение работает в обоих вариантах.
2. Supabase → **SQL Editor** → вставьте весь `supabase/schema_v2.sql` → Run. (Можно запускать повторно.)
3. В SQL Editor выполните: `select public.create_school_key('Школа №…');` — получите ключ вида `SABAK-XXXX-XXXX-XXXX`. Он показывается один раз.
4. Откройте сайт → «Создать аккаунт» → роль «Директор» → введите ключ.
5. В кабинете директора: «Доступ» → создавайте приглашения; «Загрузить демо-данные» наполнит школу тестовыми данными для показа.
6. URL и anon-ключ уже в `js/config.js` (anon-ключ публичный по дизайну; **service_role и пароль БД сюда не вставляйте никогда**).

## Обновление на Vercel
Замените файлы в репозитории GitHub (загрузить/перезаписать), Vercel задеплоит сам. После деплоя на телефоне закройте и откройте приложение дважды (обновится Service Worker).

## Честные ограничения
- Распознавание лица работает в браузере. Без «строгого режима» сервер доверяет флагу `verified`; в строгом режиме сервер сам проверяет технические параметры снимка, но не распознаёт лицо нейросетью.
- Для ученика нужна реальная почта (или почта родителя) — вход через Supabase Auth.
- Выпущенное ключом школа — единственная точка входа: храните ключ как пароль.
- PDF — через системное окно печати («Сохранить как PDF»).
- Кыргызский перевод — рабочий черновик (словарь `js/ky.js`), нужна вычитка носителем языка.
- Не загружайте реальные данные детей без согласия и правовой основы (закон КР о персональной информации).
