# Контракт глав хроники (для авторов страниц)

Корень проекта: .../scratchpad/sabak  (статический сайт, без сборки; vanilla JS + CSS; без GSAP/CDN/внешних шрифтов/внешних картинок).
Локальный сервер: `cd <корень> && python3 -m http.server 8765` (проверь `curl -s localhost:8765 -o /dev/null`; если не отвечает — запусти в фоне). Страница открывается как http://localhost:8765/updates/<slug>.html (на проде — /updates/<slug>).

## Что создаёт автор главы (ТОЛЬКО эти 3 файла на главу)
- `updates/<slug>.html` — разметка (скелет — как в updates/0-1-bashtalysh.html: head, `<body class="ch c<NN>">`, `<main id="main">`, `<nav data-chron-end></nav>`, module-скрипт: `import { Chron } from '/js/chron.js'; Chron.init('<slug>'); import('/js/chron/<slug>.js').then(m => m.default(Chron));`)
- `css/chron/<slug>.css` — весь визуальный язык главы. Подключается после /css/chron.css. Селекторы только под своим классом `.cNN`.
- `js/chron/<slug>.js` — `export default function (C) {...}` со сценами главы.
НЕ ТРОГАЙ: js/chron.js, css/chron.css, js/chron/chapters.js, чужие главы, app.html, остальной проект. Если нужно изменение общего ядра — не делай, а напиши в итоговом отчёте.

## Ядро (js/chron.js, уже есть; прочитай его и эталон 0-1-bashtalysh.{html,css,js})
Chron.init подставляет: верхнюю панель (логотип, KY/РУ, «Анимации» вкл/выкл, «Все главы»), полосу прогресса, меню глав, блок «предыдущая/следующая глава» с анимированным переходом-«занавесом», цвета главы из chapters.js (--ch-accent, --ch-bg, --ch-ink; можно переопределять в своём css). 
Помощники: `C.pin(sectionEl, (p)=>…)` — липкая сцена, p 0..1 по прокрутке секции (секция высокая, внутри `position:sticky;top:0;height:100dvh`); `C.scrub(el, cb)` — p 0..1 пока элемент проходит экран; `C.loop(el, (dt,t)=>…)` — rAF-цикл только пока элемент виден (для частиц/canvas); `C.reveal()`/класс `.cr` — появление блоков; `C.count`, `C.ease`, `C.clamp`, `C.lerp`, `C.horn(size,stroke)` / `C.hornTile(color,opacity,size)` — кошкар-муйуз (SVG / фон-плитка); `C.reduced` — prefers-reduced-motion ИЛИ ручной переключатель «Анимации»; `C.say(ru, ky)`, `C.onLang(cb)`, `C.lang()`.
Язык: добавь `data-ky="кыргызский текст"` на элементы с русским текстом, где ты уверен в переводе (заголовки, короткие подписи). Перевод — ЧЕРНОВОЙ; не пиши длинные кыргызские абзацы, если не уверен в грамматике. Финальную фразу — кыргызскую цитату — приведи ТОЧНО как в briefs.md. Динамические тексты в JS: через C.say(ru, ky) + C.onLang(перерисовать).

## Обязательная структура страницы (как в briefs.md → «Структура страницы»)
1 Hero-сцена (уникальная, липкая сцена на прокрутке) с огромным названием главы и подзаголовком/фразой из briefs.md.
2 Название + версия + дата (из briefs.md).
3 Короткая эмоциональная история обновления (2–4 предложения, строго по фактам из briefs.md, без выдумок).
4 Главная визуальная демонстрация нововведения (сцена на прокрутке).
5 Подробный список ВСЕХ фактических изменений из briefs.md (каждый пункт — отдельный элемент; ничего не выдумывай и не пропускай; формулировки простые, без технических кодов).
6 Раздел «Что изменилось» (по ролям/смыслу, только из фактов).
7 Раздел «Что исправлено» — ТОЛЬКО если в briefs.md есть исправления (0.4, 0.5, 0.5.1).
8 Интерактивная демо-зона, указанная в briefs.md: ВСЁ кликабельное работает; это симуляция на вымышленных данных, помеченная «ДЕМО» (`.demo-tag`); никаких реальных запросов к серверу, никаких настоящих персональных данных.
9 Финальная сцена + финальная фраза (кыргызский оригинал + русский перевод).
10 Предыдущая/следующая глава — делает ядро (`<nav data-chron-end>`).

## Требования качества
- Визуальный язык ГЛАВЫ уникален: своя палитра, типографика (шрифты: только Oswald 700 и Inter 400/700 из /fonts + системные стеки: serif/Georgia, ui-monospace, system-ui и т.п.; крупную выразительную типографику делай через размеры/трекинг/форму, SVG-текст, clip-path), композиция, главный визуальный эффект. Hero не должен повторять другие главы. Не используй шаблонный «cream+terracotta», «чёрный+кислотно-зелёный», одинаковые карточки с одинаковыми тенями. Кыргызские мотивы — деликатно (орнамент-фон, кошкар-муйуз, шырдак-геометрия), не «этнографический музей».
- Анимации осмысленны и связаны с релизом, на transform/opacity/clip-path/stroke-dashoffset; тяжёлые вещи (canvas/частицы) — только через C.loop, умеренный размер (≤ ~250 частиц, DPR ≤ 2), останавливаются вне экрана. Нет бесконечных WebGL. Не блокируй прокрутку.
- Reduced-motion и ручное «Анимации: выкл» (класс `body.rm`): статичный читаемый фолбэк — липкие сцены превращаются в обычные блоки (смотри блоки `@media(prefers-reduced-motion:reduce)` и `.rm …` в эталонном css), контент остаётся виден, демо остаются рабочими, без бесконечных анимаций.
- Адаптив: Desktop ≥1100, Tablet ~768, Mobile 390 — мобильная версия перекомпонована (не просто уменьшена): без горизонтального скролла страницы, кнопки ≥ 40px, текст ≥ 15px.
- Контраст текста ≥ 4.5:1; видимый :focus-visible; все кнопки — `<button type=button>`/ссылки с доступными названиями; не прячь контент от скринридера без причины.
- Производительность: нет внешних запросов, картинки только inline-SVG/CSS (никаких чужих логотипов/персонажей), HTML+CSS+JS главы вместе желательно < 150 КБ.
- Тексты без технических кодов (никаких schema/SQL/номеров ошибок/имён файлов). Не утверждай того, чего нет в briefs.md; соблюдай все «НЕ…» ограничения конкретной главы (честные оговорки!).
- Страница должна открываться без ошибок JS в консоли.

## Самопроверка (обязательна, Playwright: NODE_PATH=$(npm root -g) node script.js)
Для каждой своей главы: открой на 1280×800 и 390×800; пролистай по 12+ позициям, сохрани скриншоты в tests/out/<slug>_*.png и ПОСМОТРИ их (Read изображений; удобно склеить в контактный лист PIL); проверь: нет ошибок консоли/pageerror; нет горизонтального скролла (scrollWidth<=innerWidth); демо реагируют на клики; переключатель KY меняет тексты; `page.emulateMedia({reducedMotion:'reduce'})` — контент виден и демо работают; ссылки prev/next ведут на существующие главы. Исправь найденное. 
В конце верни короткий отчёт: что сделано по каждой главе (главный эффект, демо), что проверено, известные недочёты, нужны ли правки ядра.
