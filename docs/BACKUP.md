# Резервные копии и «усыпление» бесплатного проекта

## Два уровня копий
1. **Копия директора из приложения** (раздел «Архив» → «Резервная копия школы»). Один zip с данными своей школы. Делать раз в неделю и перед концом четверти. Хранить в двух местах.
2. **Копия всей базы на GitHub** (`.github/workflows/backup.yml`). Раз в неделю делает `pg_dump` и шифрует паролем. Подходит оператору платформы. Нужен **закрытый** репозиторий и два секрета (строка подключения к базе и пароль шифрования). Секреты вводите только в настройках GitHub, никому не присылайте.

Восстановление: `gpg -d sabak-ГГГГ-ММ-ДД.dump.gpg > sabak.dump`, затем `pg_restore --no-owner -d <новая база> sabak.dump`. Раз в квартал проверьте, что копия правда восстанавливается.

## Бесплатный проект «засыпает»
Supabase приостанавливает бесплатные проекты при долгом простое (условия смотрите в личном кабинете). Для школы это недопустимо. Решение номер один: тариф Pro. Пока этого нет, `.github/workflows/keepalive.yml` раз в два дня делает безобидный запрос и не даёт проекту уснуть. Это временная мера, а не замена тарифа.

## Что не защищено копиями
Файлы в хранилище (фото, сканы документов) в `pg_dump` не входят. Для них нужна отдельная копия через Supabase Storage (скачивание бакета) либо тариф с автоматическими копиями.
